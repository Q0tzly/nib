# ベンチマーク

nib と既存のエディタ（vim、Helix）を同じ条件で測った結果。目標は [architecture.md](architecture.md) の「性能目標」にある。

## 測り方

[bench/latency.py](../bench/latency.py) で、疑似端末（pty）越しにエディタを動かして測る。端末エミュレータの遅延は含まない。端末の大きさは 160 × 50。

| 項目 | 内容 |
|------|------|
| 起動 | 起動してから、出力が 0.3 秒止まるまで。最初の画面のあとに色を付けて描き直すエディタは、その描き直しまで含む。10 回の中央値 |
| 打鍵 | 挿入モードでファイルの先頭に `a` を 300 回打ち、キーを送ってから画面の書き出しが終わるまで |
| スクロール | 半画面スクロール（`Ctrl-d`）を 300 回。40 回ごとに `gg` で先頭に戻る |
| メモリ | macOS の `proc_pid_rusage` の物理メモリの使用量（アクティビティモニタの「メモリ」と同じ）。起動の直後と、打鍵とスクロールのあと |
| 待機 | キーを待っているあいだの 30 秒の CPU 使用率と、1 秒あたりのウェイクアップ回数（`--idle 30`） |

- 打鍵とスクロールの値は「画面の書き出しが終わるまで」。vim はスクロールで最初の数バイトをすぐに書き、残りをあとから書くので、最初のバイトまでの時間では速く見える。
- 同じマシンでも、測った時によって 3 割ほどずれる（M2.5 の作業中、injection なしの nib の打鍵が 1.25 ms のときも 1.6 ms のときもあった）。比べるときは、同じ時に測った値どうしで比べる。

### ファイル

中身が変わらないように、crates.io のクレートに入っているファイルを使う（`~/.cargo/registry/src/*/` にある）。

| 名前 | ファイル | 行数 | 特徴 |
|------|----------|------|------|
| Rust 大 | ropey 1.6.1 `src/rope.rs` | 3,455 | ドキュメントコメント 592 行 |
| Rust 小 | 上の先頭 20 行（`head -n 20`） | 20 | |
| テキスト | 「Rust 大」を `rope.txt` に写したもの | 3,455 | 構文ハイライトなし。ハイライトの費用を見るため |
| Markdown | ratatui 0.29.0 `CHANGELOG.md` | 6,969 | コードブロック約 360、行内のコード約 1,000 |

### 再現

```sh
cargo xtask build-plugins
cargo build --release
R=$(echo ~/.cargo/registry/src/*/)
python3 bench/latency.py $R/ropey-1.6.1/src/rope.rs --idle 30 vim hx nib
python3 bench/latency.py $R/ratatui-0.29.0/CHANGELOG.md vim hx nib
cargo test --release -p nib-core --test syntax startup_breakdown -- --ignored --nocapture
cargo test --release -p nib-core --test plugins key_latency -- --ignored --nocapture
```

## 結果

2026-09-26、Apple M1 Pro、macOS 27.0。vim 9.1（`--clean`、構文ハイライトあり）、Helix 25.07.1（LSP を切る）、nib 0.8.7（標準プラグインだけ）。

### Rust 大（3,455 行）

| 項目 | vim | Helix | nib |
|------|-----|-------|-----|
| 起動 | 34 ms | 167 ms | 68 ms |
| 打鍵（中央値 / p99） | 6.82 / 15.69 ms | 15.77 / 20.93 ms | **0.94 / 2.99 ms** |
| スクロール（中央値 / p99） | 2.84 / 7.83 ms | 2.36 / 6.29 ms | **1.35 / 5.81 ms** |
| メモリ（起動 / 操作のあと） | 5.8 / 5.8 MB | 23.3 / 23.4 MB | 27.4 / 22.8 MB |
| 待機中の CPU | 0.002 %、0.1 回/秒 | 0.000 %、0.0 回/秒 | 0.010 %、0.2 回/秒 |

### Rust 小（20 行）

| 項目 | vim | Helix | nib |
|------|-----|-------|-----|
| 起動 | 45 ms | 88 ms | 47 ms |
| 打鍵（中央値 / p99） | 7.27 / 15.64 ms | 2.08 / 5.63 ms | **0.62 / 2.51 ms** |
| メモリ（起動 / 操作のあと） | 5.6 / 5.7 MB | 16.7 / 17.3 MB | 22.6 / 17.2 MB |

スクロールは、画面に収まるファイルでは何も動かないので測らない。

### テキスト（3,455 行、ハイライトなし）

| 項目 | vim | Helix | nib |
|------|-----|-------|-----|
| 起動 | 43 ms | 30 ms | 33 ms |
| 打鍵（中央値 / p99） | **0.27 / 0.67 ms** | 0.84 / 2.40 ms | 0.56 / 1.39 ms |
| スクロール（中央値 / p99） | **0.47 / 3.41 ms** | 1.42 / 3.70 ms | 0.73 / 2.76 ms |
| メモリ（起動 / 操作のあと） | 5.6 / 5.7 MB | 12.8 / 13.4 MB | 15.2 / 14.7 MB |

### Markdown（6,969 行）

| 項目 | vim | Helix | nib |
|------|-----|-------|-----|
| 起動 | 48 ms | 399 ms | 143 ms |
| 打鍵（中央値 / p99） | **0.37 / 0.92 ms** | 79.95 / 108.55 ms | 2.02 / 6.54 ms |
| スクロール（中央値 / p99） | 1.90 / 4.35 ms | 2.28 / 5.18 ms | **1.55 / 3.85 ms** |
| メモリ（起動 / 操作のあと） | 6.6 / 6.7 MB | 50.8 / 53.2 MB | 37.3 / 40.9 MB |

vim の Markdown のハイライトは正規表現で、コードブロックの中を別の言語で色付けしない。Helix と nib は、コードブロックと行内の要素を別の構文木で読む（injection）。

### 読み取れること

- ハイライトのあるファイルでは、nib の打鍵がいちばん速い。vim と Helix は、ハイライトなしなら 1 ms 未満だが、ハイライトがあると数 ms から数十 ms になる。構文木を差分で更新し、ハイライトのクエリを表示範囲にだけ掛けているのが効いている。
- Helix は、injection の多い Markdown で打鍵が 80 ms になる（原因は調べていない）。nib は、画面の近くの層だけを解析して持つことで 2 ms に抑えている（[architecture.md](architecture.md) の「構文木」）。
- 起動は、文法の読み込み（キャッシュがあっても言語ごとに数 ms から十数 ms）と最初の解析が大半を占める。Markdown の起動が遅いのは、6,969 行の解析と、injection を探す最初のクエリのため。
- メモリは vim の 3〜6 倍。WASM の実行環境（wasmtime）と、プラグインごとのインスタンスの分。

### injection の費用

同じ時に、injection を外した nib（言語プラグインの `injections` を消したもの）と比べた。

| ファイル | 項目 | injection なし | あり |
|----------|------|----------------|------|
| Rust 大 | 起動 | 49 ms | 68 ms |
| Rust 大 | 打鍵（中央値 / p99） | 0.83 / 3.76 ms | 0.94 / 2.99 ms |
| Rust 大 | スクロール（中央値 / p99） | 0.68 / 2.98 ms | 1.35 / 5.81 ms |
| Markdown | 起動 | 104 ms | 143 ms |
| Markdown | 打鍵（中央値 / p99） | 1.29 / 4.85 ms | 2.02 / 6.54 ms |
| Markdown | スクロール（中央値 / p99） | 1.19 / 5.95 ms | 1.55 / 3.85 ms |

起動の差は、Markdown の文法 2 つの読み込みと、画面の中の層の最初の解析。Rust の色は injection を待たずに先に付く。

## nib の内訳

### 起動の内訳

`startup_breakdown`（プロセスの中で測る。ファイルは nib の `core/src/render.rs`、847 行）。

| 段階 | キャッシュなし | あり |
|------|----------------|------|
| helix プラグインの読み込み | 57.0 ms | 2.9 ms |
| rust と markdown の登録（文法はまだ読まない） | 5.0 ms | 0.5 ms |
| ファイルを開く | 0.1 ms | 0.04 ms |
| 最初の画面（色なし） | 0.08 ms | 0.08 ms |
| Rust の文法の読み込み、解析、色つきの描画 | 38.6 ms | 24.1 ms |
| Markdown の文法の読み込み、画面の中のドキュメントコメントの解析、描画 | 153.2 ms | 9.5 ms |
| 合計 | 254 ms | 37 ms |

キャッシュは WASM のコンパイル結果。初回の起動だけがキャッシュなしになる。

### プラグインを通る 1 打鍵

`key_latency`: テスト用のプラグイン（test-insert）でキーを受けて文字を挿入する 1 回が 3.4 µs。プラグインを通すこと自体の費用は、打鍵の全体（約 1 ms）から見て小さい。

### 大きさ

| もの | 大きさ |
|------|--------|
| `nib` の実行ファイル（release、標準プラグインと文法を埋め込み） | 36.6 MB |
| Helix（`hx` と、別に置く文法 `runtime/grammars`） | 15.5 MB + 190 MB |
| vim | 8.1 MB |

埋め込んでいる標準プラグイン（WASM の合計）:

| プラグイン | 大きさ | プラグイン | 大きさ |
|------------|--------|------------|--------|
| bash | 1,326 KB | markdown（ブロックと行内） | 828 KB |
| rust | 1,092 KB | lsp | 370 KB |
| python | 447 KB | helix | 327 KB |
| go | 212 KB | indent | 188 KB |
| yaml | 185 KB | picker | 108 KB |
| toml | 23 KB | json | 5 KB |

## 目標との比較

条件は Rust 大（3,455 行、ハイライトあり）。

| 指標 | 目標 | 今 |
|------|------|-----|
| 挿入モードの打鍵 | 中央値 2 ms 未満、p99 8 ms 未満 | 0.94 / 2.99 ms |
| スクロール | 中央値 2 ms 未満、p99 8 ms 未満 | 1.35 / 5.81 ms |
| 起動から最初の描画まで（キャッシュあり） | 100 ms 未満 | 68 ms（色付けまで） |
| 1 つのプラグインが 1 回のイベントに使う時間 | 1 ms 未満を目安 | 3.4 µs（test-insert） |

Markdown（6,969 行）でも、打鍵は中央値 2.02 ms、p99 6.54 ms と、目標の近くにある。

## これまでの推移

各マイルストーンを終えたときに記録した値（[roadmap.md](roadmap.md)）。条件は Rust 大で、そのときの機能での値。測った時が違うので、上のずれの幅を見込んで読む。

| 時点 | 起動 | 打鍵（中央値 / p99） | スクロール（中央値 / p99） | そのときの状態 |
|------|------|----------------------|----------------------------|----------------|
| M0.2 | 10 ms | | | 表示だけ。プラグインもハイライトもない |
| M0.3 | 15.5 ms | 0.97 / 1.68 ms | | テスト用のプラグインで文字を挿入 |
| M0.4 | 9.9 ms | 0.73 / 2.44 ms | | helix プラグインを埋め込み |
| M1 | 13.1 ms | 0.87 / 3.90 ms | 1.14 / 5.72 ms | 待機中の CPU は 0.008 % |
| M2.1 | 58.9 ms | 1.81 / 6.67 ms | 1.30 / 4.82 ms | 構文ハイライト |
| M2.3 | | 2.41 / 5.26 ms | | 対応する括弧の強調 |
| M3.2 | | 1.29 / 6.16 ms | | 入力の読み取りを別のスレッドに |
| M2.5 | 68 ms | 0.94 / 2.99 ms | 1.35 / 5.81 ms | injection（この文書の結果） |

M2.2 では、構文木を使う操作を別に測った: `]f` が 3.6 ms、`Alt-o` が 2.6 ms。
