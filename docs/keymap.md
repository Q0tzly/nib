# キーマップ

> ステータス: 草案。末尾の「要確認」は未決。

モーダル編集をプラグインでどう実現するかを決める。最初の標準プラグインは Helix 風キーマップ（`plugins/helix`、プラグイン名 `helix`）。

## コアとキーマッププラグインの分担

| コア | キーマッププラグイン |
|------|------------------------|
| キーを入力スタックに流す | 入力スタックのいちばん下の層として、すべてのキーを受け取る |
| 選択、トランザクション、undo の履歴 | モードと、押しかけのキー（`g` を押して次を待っている状態など） |
| 縦移動、スクロール、検索、書記素の境界 | 単語移動や文字検索（`f`）のような、テキストだけで決まる移動 |
| カーソルの形とステータスラインを描く | モードに応じて、カーソルの形とステータスラインの中身を指定する |

コアはモードを知らない。「ノーマルモード」「挿入モード」は、キーマッププラグインの内部状態にすぎない。

## Helix 風キーマップの内部構造

### 状態

プラグインが持つ状態は次のとおり。

- 現在のモード（ノーマル・挿入・選択）
- 押しかけのキー列と、回数の前置き（`3w` の `3`）
- レジスタ（`y` でコピーした内容）
- 直前の検索パターン、直前の文字検索（`f` / `t`）
- 挿入を始めたかどうか（undo の単位をまとめるため）

### キーの解釈

1. モードごとにキー列からアクションへの木を持つ。既定の配置に、設定の上書きを重ねて作る。
2. キーが届いたら、押しかけのキー列に足して木をたどる。
   - 途中の節なら、続きを待つ。
   - 葉ならアクションを実行し、キー列を空にする。
   - 木にないなら捨てる。
3. 挿入モードでは、木にない文字キーをそのまま挿入する。

### アクション

アクションは 2 種類ある。

- **組み込み**: 単語移動や削除のように、プラグインの中で実装するもの。すべて `helix.<名前>` のコマンドとしても登録し、他のプラグインや設定から呼べるようにする。
- **コマンド**: `buffer.save` や、他のプラグインの `lsp.goto_definition` のように、名前で呼ぶもの。

名前は Helix のコマンド名（`move_next_word_start` など）に合わせる。

### 複数選択

移動や編集は、すべての選択範囲に同じように適用する。

- 移動では、各範囲の新しい位置を計算し、`set-selection` を 1 回だけ呼ぶ。
- 編集では、全範囲の `edit` を 1 つのトランザクションにまとめる。

### undo の単位

- ノーマルモードの編集（`d`、`c`、`p` など）は、1 回ごとに `new-step`。
- 挿入モードでは、入ってから最初の編集を `new-step`、以降を `merge` にする。挿入全体が 1 手になる。

### モードの知らせ方

モードが変わったら、次の 3 つを行う。

1. `set-cursor-shape` でカーソルの形を変える（ノーマルはブロック、挿入はバー）。
2. `ui.set-status` でステータスラインのモード表示を更新する。
3. `helix.mode_changed` の `custom` イベントを出す。他のプラグインがモードに合わせて動けるようにするため。

## 設定

config.toml の `[plugins.helix]` に書く。キーの書き方は Helix の `[keys.*]` と同じにする。

```toml
[plugins.helix]
tab-width = 4
indent = "spaces"

[plugins.helix.keys.normal]
"C-s" = "buffer.save"
g = { a = "goto_last_accessed_file" }   # 表は前置きキーになる

[plugins.helix.keys.insert]
j = { k = "normal_mode" }
```

ドットを含まない名前は、helix プラグイン自身のコマンドとして解釈する。実装済みのコマンドの範囲であれば、Helix の設定をそのまま貼り付けて使える。

## M1 で実装するキー

Helix の既定の配置のうち、nib 自身のソースを編集するのに必要なものに絞る。

| 分類 | キー |
|------|------|
| 移動 | `h` `j` `k` `l`、矢印キー、`w` `b` `e` `W` `B` `E`、`f` `t` `F` `T` |
| ジャンプ | `gg` `ge` `gh` `gl` `gs`、`Ctrl-d` `Ctrl-u`、`Ctrl-f` `Ctrl-b` |
| 選択 | `x`、`%`、`;`、`,`、`Alt-;`、`C`、`s`、`v`（選択モード） |
| 編集 | `i` `a` `I` `A` `o` `O`、`d` `c` `y` `p` `P`、`r`、`>` `<`、`J` |
| undo | `u` `U` |
| 検索 | `/` `?` `n` `N` `*` |
| 対応括弧 | `mm`、`mi` / `ma`（括弧と引用符。テキストだけで判定する） |
| バッファ | `gn` `gp` |
| 回数 | `3w`、`5j` などの前置き |
| コマンドライン | `:w` `:q` `:q!` `:wq` `:o <path>` |
| 挿入モード | 文字、`Enter`（前の行のインデントを引き継ぐ）、`Backspace`、`Tab`、矢印キー、`Esc` |

M1 のあとに回すもの:

- ファイル選択などのスペースメニュー（コアの非同期ファイル列挙が必要）
- LSP を使う操作（`gd` など）
- 構文木を使う操作（`maf`、`Alt-o` など）
- システムのクリップボード
- `.` による繰り返し
- 名前つきレジスタ（`"a`）
- 押しかけのキーの候補表示（ポップアップとタイマーが必要）

## コマンドライン

`:` で始まるコマンドラインは、M1 では helix プラグインの一部として実装する。

1. `:` を押すと `ui.open-panel` でパネルを開き、入力スタックに層を 1 つ積む。
2. 入力中のキーはその層で受け取り、パネルの中身とカーソルを更新する。
3. `Enter` で入力を解釈してコマンドを呼び、層を外してパネルを閉じる。

| 入力 | 呼ぶコマンド |
|------|--------------|
| `:w` | `buffer.save` |
| `:o <path>` | `buffer.open` |
| `:q` | `editor.quit` |

コマンドラインを独立したプラグインに分けるかどうかは、他のプラグインからもコマンドラインを使いたくなった時点で考える。

## ほかの編集モデルでも成り立つか

この仕組みが Helix 専用になっていないかを、vim 風キーマップで確かめておく。

- vim のカーソルは、幅 1 の選択として表せる。ビジュアルモードは、Helix の選択モードと同じく選択を広げるだけ。
- `d` を押して移動を待つ状態（operator-pending）は、プラグイン内のキー列の木と状態で表せる。`dw` は「`w` の移動範囲を計算して、その範囲を削除する」になる。
- `.` による繰り返しは、プラグインが直前の操作を記録すればよく、コアの支援は要らない。

コアに足りないものは見当たらない。vim 風キーマップは、作る必要が出たら別のプラグインとして作れる。

## 要確認

- **検索をコアに置く**: `/` や `s` の正規表現検索は、`buffer.find` / `buffer.find-all` としてコアが提供する（plugin-api.md に追記した）。プラグインが自前で検索すると、大きなバッファの全文を毎回コピーすることになる。検索は複数のプラグインが使う基盤でもあるので、コアに入れる基準に当てはまる。
- **Helix の設定との互換**: キーの書き方と、コマンドの名前を Helix に合わせる。vision.md の「互換を目指さない」は vim / emacs に対するもので、これはキーマッププラグインの中での便宜。
